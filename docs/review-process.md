# Процесс ревью

Каждая глава проходит минимум два цикла ревью до статуса `готово`. Ни одна глава не попадает в сборку для Литрес без записи ревью в `reviews/`.

## Цикл

1. **Черновик** RU (автор или агент по `docs/style-guide.md`).
2. **Ревью-1** — параллельно, независимо, каждый ревьюер не видит других:
   - **Редактор** — ясность, длина, вода, структура «суть → мостик → шаг → повтор», стайлгайд.
   - **Фактчекер** — каждое утверждение о платформах, ценах, исследованиях, книгах: есть ли источник, верна ли дата, не выдуман ли кейс. Проверяет по первоисточникам.
   - **Целевой читатель** — «инди-разработчик с ботом и без бюджета»: понятно ли, что делать завтра, где потерялся, где скучно.
   - **Эксперт-практик** (growth / маркетинг) — не упрощено ли до неверного, чего не хватает, где опасный совет.
   - **Внешний ревьюер** — Астра (`codex:gpt-6-astra`) через `review-cli`, когда доступна: `review just-ask "$(cat reviews/prompts/common.md) $(cat book/ru/<file>)" --task BOOK-<id> -m astra`.
3. **Сводка** — `reviews/<дата>-round-N.md`: каждое замечание, решение (принято / отклонено + почему), severity (blocker / major / minor).
4. **Правки** — все blocker и major закрыты; minor — по решению.
5. **Ревью-2** — те же роли смотрят diff и сводку: закрыты ли замечания, не появилось ли новых проблем.
6. **EN** — пишется после того, как RU прошёл ревью-2 (оригинальный текст по той же структуре, не перевод); ревью EN — редактор (native-level English) + сверка структуры с RU.
7. Статус главы в `docs/outline.md` → `готово`.

## Критерий выхода

- 0 blocker, 0 major в последнем раунде.
- Каждое утверждение с цифрой — с источником или пометкой «ориентир».
- Шаг главы выполним за вечер без покупок.
- RU и EN совпадают по структуре (заголовки, врезки, шаги).

## Шаблон записи раунда

```markdown
# Ревью: 2.1 Атрибуция — раунд 1 (2026-09-27)

| # | Ревьюер | Severity | Замечание | Решение |
|---|---|---|---|---|
| 1 | Фактчекер | blocker | … | принято, исправлено в §2 |
```
